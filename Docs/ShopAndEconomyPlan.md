## 2. Решения

- **Три величины.** Качество — `WaffleScore.Percent` (внутреннее, не меняется). Очки смены — результат обслуживания, показываются в итогах, копятся в статистике, **не тратятся**. Деньги — единственная валюта, тратятся в магазине.
- **Начисление один раз.** Заказы и подарки за смену пишутся в журнал смены (`ShiftLedger`) с ключом (`d3-v5` — визит, `story:<id>:<n>` — сюжетное действие). Повторная запись того же ключа игнорируется. В кошелёк журнал переносится один раз, в `DayRunner.EndDay` → `GameProgress.CommitShift(day)`; повторный вызов для того же дня ничего не делает (`lastCommittedDay`). Итоги — только отчёт.
- **Сохранение** — `GameProgress` (JSON в `persistentDataPath`, версия, запись через временный файл + резервную копию). Ничего похожего в проекте не было. Сюжетные флаги, «визит был», выданные награды фиксируются вместе с деньгами при завершении смены: если игру закрыли посреди дня, день начинается заново, ничего не теряется и не выдаётся дважды.
- **Конфигурация отдельно от импорта.** `EconomySettings` (числа экономики), `ShopCatalog` (товары, уровни, цены, эффекты, стартовый набор), `DecorStationLayout` (геометрия стола). Импорт эти ассеты не трогает; товар-ингредиент ссылается на `CraftIngredient`, ключ в сохранении — `id` сайта.
- **Эффекты улучшений** — через `GameStats` (стат → сумма модификаторов купленных уровней → ограничение min/max из каталога). Мини-игры читают стат при старте действия.
- **Второе место для украшения**: клиент по-прежнему один. Из одной миски теста можно испечь вторую вафлю для того же заказа (ещё раз налить тесто и испечь), положить её на второе место, украсить независимо и отдать любую из двух. Каждая вафля — `WaffleProduct` со своим тестом, выпечкой, украшением и ключом заказа; упаковка проверяет ключ. Неотданная вафля выбрасывается после выдачи заказа.
- **Ориентация** — только горизонтальная (вся вёрстка под 16:9, на 4:3 стол листается).
