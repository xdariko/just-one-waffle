# Баланс экономики: стартовая гипотеза

> Это **расчёт по формулам игры**, а не результат плейтеста. Числа — первая настройка; их нужно проверять игровыми прогонами.
> Таблицы смен ниже посчитаны тем же кодом, что и в игре (`OrderPayout.Compute`, `EconomySettings.PriceOf`, цены из `ShopCatalog`), временным скриптом в batchmode.

## Три величины

| Величина | Что это | Где считается | Тратится? |
|---|---|---|---|
| **Качество** | доля баллов мини-игр (+3 зелёная / +1 жёлтая / 0 красная), `WaffleScore.Percent` | `RecipeScoring` | нет, внутренняя |
| **Очки смены** | результат обслуживания: сумма очков за заказы, рекорд дня и общий счёт в сохранении | `EconomySettings` (`*Points`) | нет |
| **Деньги** | единственная валюта, магазин | `GameProgress.Money` | да |

Очки в деньги не превращаются. Опыта и уровней игрока в проекте нет — новую систему не вводили.

## Формулы

```
исход  = нарушено требование заказа ? Violation
         : по настроению клиента (WaffleRules: качество ≥ 80% → Happy, ≥ 50% → Neutral, ниже → LowQuality)

цена   = OrderTemplate.price, если > 0
         иначе defaultOrderPrice + decorComponentBonus × (обязательные соусы + добавки + группы "любой с тегом" рецепта-ориентира)

оплата = round(цена × доля[исход])                                         — 0, если у визита paysForOrder = false
чаевые = round(цена × lerp(tipMinRate, tipMaxRate, (q − tipFromQuality) / (1 − tipFromQuality)))
         только если требования выполнены и q ≥ tipFromQuality                — 0, если paysForOrder = false
очки   = очки[исход]                                                          — 0, если awardsPoints = false

заработок смены = Σ оплата + Σ чаевые + Σ сюжетные подарки (GiveMoney)
кошелёк        += заработок смены — один раз, при закрытии смены (DayRunner.EndDay → GameProgress.CommitShift)
```

**Нарушение требования** (нет нужного соуса, сахар в «без сахара», сырая/сгоревшая вафля) даёт исход `Violation` при любом качестве: 25% цены, без чаевых и очков. Высокое качество его не компенсирует.

## Стартовые значения (`Assets/ScriptableObjects/Economy/EconomySettings.asset`)

| Параметр | Значение | Поле |
|---|---|---|
| Деньги в начале новой игры | **20** | `startingMoney` |
| Бесплатный стартовый набор | яйцо, мука, молоко, сахар, соль + шоколадный соус, сгущёнка, клубника, банан | `ShopCatalog.startingIngredients` |
| Цена простого заказа | **20** | `defaultOrderPrice` |
| Надбавка за каждое обязательное украшение | **+5** | `decorComponentBonus` |
| Оплата: доволен / так себе / низкое качество / нарушение | **100% / 75% / 40% / 25%** цены | `happyPay`, `neutralPay`, `lowQualityPay`, `violationPay` |
| Чаевые | от **10%** цены при качестве 80% до **40%** при 100%, линейно | `tipFromQuality`, `tipMinRate`, `tipMaxRate` |
| Очки: доволен / так себе / низкое / нарушение | **10 / 5 / 2 / 0** | `happyPoints`… |
| Ежедневные расходы | нет | — |

Цены заказов при этих числах:

| Заказ | Цена | Вес | С дня | Нужно открыть |
|---|---|---|---|---|
| plain, crispy, no_sugar, crispy_no_sugar | 20 | 1 | 1 | — |
| strawberry_chocolate, fruit | 30 | 1 / 0.7 | 1 | — (клубника/банан в стартовом наборе) |
| caramel_crispy | 25 | 1 | 2 | Карамель |
| ice_cream | 25 | 1 | 1 | Мороженое |
| festive | 30 | 0.8 | 1 | Посыпка |
| honey_crispy | 25 | 0.8 | 2 | Мёд |

Средняя цена выпавшего заказа (по весам): **23.0** со стартовым набором, **24.2**, когда открыто всё.

Примеры одного заказа за 20: доволен при 100% → 20 + 8 чаевых, 10 очков; доволен при 80% → 20 + 2; так себе → 15; нарушение при качестве 100% → 5, без чаевых.

## Магазин (`Assets/ScriptableObjects/Shop/ShopCatalog.asset`)

### Улучшения мини-игр

Значение уровня — итоговое (не прибавка к прошлому). Эффекты разных товаров на один стат складываются и ограничиваются пределом из `ShopCatalog.stats`.

| Мини-игра | Улучшение (`id`) | Уровни · цена | Эффект | Предел |
|---|---|---|---|---|
| Яйца | Ловкие пальцы (`egg_luck`) | 60 / 110 / 180 | шанс поймать скорлупу **20% / 35% / 50%** | 60% |
| Мука, молоко, сахар, тесто | Мерная посуда (`pour_scale`) | 70 / 130 / 200 | допуски зелёной и жёлтой зон шире на **15% / 30% / 45%** (и на шкале, и в оценке) | +60% |
| Перемешивание | Удобный венчик (`whisk_balance`) | 60 / 110 / 180 | зелёная зона шире на **±0.03 / 0.06 / 0.09** шкалы; прощается **0.3 / 0.6 / 0.9 с** перемешивания | ±0.10, 1 с |
| Выпечка | Таймер вафельницы (`bake_timer`) | 80 / 140 / 220 | «золотистое» окно **8–12 / 7.5–12.5 / 7–13 с** (было 8.5–11.5); «бледная» и «зажаристая» сдвигаются, не сужаясь | ±2 с |
| Украшение (соусы) | Широкая кисть (`decor_brush`) | 50 / 100 | кисть шире на **20% / 40%** | +50% |
| Соль, перенос миски, упаковка | — | — | одно нажатие или перенос без ошибки и навыка — улучшение не придумывали | — |

**Удача (яйца).** Проверка запускается один раз на удар яйца о край миски, если скорость удара выше `cleanMaxSpeed` (без улучшения такой удар всегда даёт «скорлупа в тесте»). Вероятность — стат `EggShellSaveChance`. Успех: яйцо засчитывается разбитым с трещиной (`Good`, жёлтая зона), скорлупы в тесте нет, над миской «Повезло!». Идеальным (`Perfect`) удача яйцо не делает. Каждый кадр ничего не бросается.

**Чего улучшения не делают.** Норма рецепта не меняется. Запреты заказа проверяются отдельно (`OrderEvaluator` по порогам `WaffleRules`), поэтому сахар в «без сахара» остаётся нарушением при любых покупках.

## Расчёт смен

Предположения (не проверены плейтестом):
- смена 240 с; время идёт в диалоге, на кухне и в реакции;
- новичок тратит ≈80 с на заказ → **3 заказа**, каждый 3-й с нарушением, качество 55–82%;
- средний игрок ≈60 с → **4 заказа**, одно нарушение на 2 смены, качество 75–90%;
- опытный ≈45 с → **5 заказов**, без нарушений, качество 90–97%;
- день 2: один из заказов — бесплатная просьба студента; день 4 — его подарок 100 (если помощь удалась);
- средняя цена заказа растёт от 23.0 к 24.2 по мере открытия ингредиентов;
- порядок покупок: Ловкие пальцы 1 → Карамель → Таймер 1 → **Второе место** → Черника → Мерная посуда 1 → Мороженое → Венчик 1 → …; не хватает денег — копим на следующий пункт.

### Сверка с ориентирами

| Ориентир | Расчёт |
|---|---|
| Первая полезная покупка — после 1–2 нормальных смен | после 1-й смены у всех трёх профилей (69 / 119 / 169 при самой дешёвой полезной покупке 50–60) |
| Заметное расширение — несколько смен | второе место: опытный — после 4-й, средний — после 6-й, новичок — после 10-й смены |
| Выбор «улучшение или ингредиент» | после 1-й смены хватает на один товар из 50–70; Карамель (70) и Ловкие пальцы (60) конкурируют |
| Неудачная смена не останавливает игру | расходов нет; даже смена из одних нарушений даёт 25% цены за заказ, новичок копит дальше |

**Что проверить плейтестом:** реальное число заказов за 240 с (особенно у новичка), частоту нарушений, не слишком ли быстро опытный игрок скупает улучшения (к 10-й смене у него 9 из 18 уровней), и не слишком ли долго новичок копит на второе место.

## Где менять

| Что | Где |
|---|---|
| Деньги на старте, цена заказа, доли оплаты, чаевые, очки | `ScriptableObjects/Economy/EconomySettings.asset` |
| Цена конкретного заказа | `OrderTemplate.price` (0 — по формуле) |
| Товары, уровни, цены, тексты эффектов, условия (день, другой товар), стартовый набор, пределы эффектов | `ScriptableObjects/Shop/ShopCatalog.asset` |
| Сюжетные подарки и флаги | `StoryVisit.onSuccess / onFailure / actions` |

| Пороги «доволен / так себе» | `ScriptableObjects/Day/WaffleRules.asset` |

После правки — **Tools → Waffle → Проверить контент**: она проверит id, цены, пределы и доступность заказов.
